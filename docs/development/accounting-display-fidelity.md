# Native accounting display fidelity

Step 50 adds 66 native precision observations: 42 exact matches and 24 explicit rejections. The stricter stored-precision policy changes the old corpus to 26 matches/four rejections without modifying its evidence. See [verification](step50-verification.md).

Step 49 retains actual Microsoft Excel 16.0 build 20326 observations in `tests/TsekSheet.Workbooks.Tests/ReferenceCorpus/AccountingDisplay/`. These are artificial workbooks only. `capture.json` records literal expected Text, observed Text, Value2, NumberFormat, Formula, workbook date system, provenance and input/output SHA-256. Two output XLSX files bind the comparison to actual saved native bytes.

Reproduction: run `scripts/Capture-AccountingDisplays.ps1` in an interactive local PowerShell session with registered Excel. The script accepts no input file paths and creates new owned synthetic workbooks under a unique ignored artifact directory. Events, links and macros are disabled (`EnableEvents=false`, `AskToUpdateLinks=false`, `AutomationSecurity=3`, Open UpdateLinks=0/read-only). Column width is 48 characters. It saves a generated input, reopens it read-only, captures cell properties and saves a separate copy. Original input hashes are checked afterward. Finally it closes its own workbook and quits/releases its Excel application. No existing Excel processes are killed. Synthetic artifacts are intentionally retained for audit rather than deleted as temporary data.

Fifteen cases in each of the 1900/1904 systems cover comma-separated amounts, peso currency, negative parentheses, zero dash/blank, percentages, decimal precision, leading-zero text, dates, date-time, locale syntax and a formula with a cached numeric result. Literal expectations are specified before capture. All 30 observed native Text values match them exactly; there is no tolerance or text normalization in comparison.

Before the correction, inspection matched only eight cases and rejected 22. Excel serialized supported punctuation as `\(`, `\)`, `\ ` and `\-`, and serialized `0.00%` using built-in format ID 10. The narrow correction recognizes only those escaped literal characters outside quoted literals, before applying the existing whitelist, and maps built-in percent IDs 9/10. Stored source format codes and values are untouched. The final regression requires **28 exact matches, two explicit locale-format rejections and zero supported-display divergences**. A test that rejects every case cannot pass.

This qualifies only the compared values/formats in this Excel environment. It does not establish general Excel rounding, locale, width, currency, alignment or precision equivalence. Date normalization policies and fictitious-day warnings remain separate. Conditional/color/fill operators, arbitrary locales and unsupported shared formulas stay raw with warnings. Numeric tolerances are not used to hide differences. Editing eligibility is unchanged.
