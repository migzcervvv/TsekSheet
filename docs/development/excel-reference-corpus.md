## Declared Excel operation and actual findings

The reference procedure performs whole-row insertion, copies the explicit template's styles/height, clears copied contents, maps approved literal values, explicitly extends the selected section SUM and preserves that subtotal's original number format. It records Excel's raw formulas **before** the explicit subtotal adjustment. This separates Excel's actual insertion behavior from the application's declared aggregation policy.

Observed raw boundary insertion does **not** automatically extend `SUM(E16:E21)` to include the row inserted at 22. The explicit business operation extends it. Interior insertion and tested relative/absolute/mixed references match the literal expectations. Excel `CalculateFullRebuild` verified selected totals **225** for one row / **250** for two rows, with downstream summaries **425** / **450**. This is recalculation evidence for those generated fixtures only; TsekSheet has no new calculation engine and still removes candidate formula caches.

Excel formula assignment initially autoformatted the subtotal; the procedure was corrected to preserve its pre-operation format as required by the declared operation. This is an explicit operation step, not normalization of the private workbook or forced formula expectations.

The read-only comparison resolves strings/types and compares formulas, ordering, selected style properties (number formats, font, fill, bottom border/color, alignment), heights, worksheet names/order/visibility, names, tables, merges and filter ranges. Two exact equivalent format encodings are normalized: built-in ID 4 versus `#,##0.00`, and escaped versus unescaped date hyphens. Arbitrary format differences are not ignored.

All four cases match the compared business/formula/style projection, but **saved Excel row heights are 21.95 where the TsekSheet package retains 22**. The comparison reports those measured differences; a small-difference diagnostic bound is not a production preservation allowance. The strict production oracle's row-height comparison was not relaxed. Therefore these are qualified reference matches, **not full structural equivalence** or broad Excel certification.

`semantic-comparison-v3.json` fingerprints the verifier and Excel evidence and lists added/removed/changed package parts and changed relationship parts. Excel adds a calculation chain, changes metadata/style/shared-string/theme serialization and relationships. Its whole package is not expected to match TsekSheet bytes. These native outputs are read-only reference artifacts; they do not bypass the application's calculation-chain/advanced-content restrictions. The TsekSheet candidate oracle continues to require unchanged unaffected package parts and explicit allowed changes.

## Reproduction and retention

Run `dotnet test tests/TsekSheet.Workbooks.Tests -c Release --filter FullyQualifiedName~ReferenceCorpusTests`. The generator derives an artifact-directory identity from specification/generator/editor/oracle/procedure fingerprints. It can seed matching retained fixtures into a new ignored artifact directory, checks every fingerprint, builds fresh current-editor candidates and tests their literal expectations/oracle acceptance. It never overwrites retained inputs or references. Seeding was exercised by preserving the original capture directory and rebuilding the local corpus from the retained bundle **without launching Excel**.

If implementation fingerprints change, the new version has pending Excel references until separately captured. A lack of Excel evidence is an explicit inconclusive comparison, not a synthetic reference relabeled as native Excel. Existing versions are retained, not overwritten.

For a new generated version, use:

```powershell
dotnet test tests/TsekSheet.Workbooks.Tests -c Release --filter FullyQualifiedName~GenerateAndValidateProvenanceTrackedCorpus --logger 'console;verbosity=detailed'
# Use the REFERENCE_CORPUS directory printed by that run:
./scripts/Verify-ExcelReferenceCorpus.ps1 -CorpusDirectory '<printed generated directory>'
dotnet test tests/TsekSheet.Workbooks.Tests -c Release --filter FullyQualifiedName~ReferenceCorpusTests
```

The script accepts only owned artifact directories under the repository, rejects redirected paths and unknown input provenance, verifies hashes, refuses existing Excel processes/output files, disables macros/events/link updates, opens generated inputs read-only, creates new reference outputs, closes without saving input and quits its own Excel instance. It does not kill another Excel process. Source hashes are checked after closing. Excel may need time to exit before another capture; a temporary process-presence rejection was observed and resolved after read-only inspection showed it had exited.

When Excel is unavailable or cannot be safely automated, keep reference status pending. A human can follow the same declared steps on generated inputs only: record Excel version, input hashes, exact whole-row operation, raw formulas before explicit range expansion, formatting preservation, mapped literals, recalculation and new-file output hashes. Do not substitute ClosedXML or TsekSheet output for Excel evidence. Capture metadata/procedure deviations and run independent comparison before accepting it as a reference.
